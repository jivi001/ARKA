# ARKA Phase 3 — OWASP Top 10 for LLM Applications Traceability Stub

**Status:** Paper-only planning stub. **No Phase 3 LLM/agent controls are implemented or accepted by this document.**  
**Purpose:** Give Phase 3 an initial review checklist without pulling LLM gateway or autonomous-agent work into Phase 2.  
**Taxonomy baseline:** OWASP Top 10 for LLM Applications (2025). Confirm taxonomy version during the Phase 3 architecture checkpoint before converting this stub into formal requirements.

## Category-to-threat planning map

| OWASP LLM category | Existing ARKA P0 threat/control references | Planned Phase 3 control owner / design area | Phase 3 planning notes |
|---|---|---|---|
| **LLM01 — Prompt Injection** | `THREAT-PROMPT-INJECTION` → `CTRL-PROMPT-GUARD-001` → `TEST-PROMPT-INJECTION-001` / `GATE-PROMPT-GUARD-001`; status `PENDING(phase=3)` | LLM Gateway / prompt-boundary owner | Treat direct and indirect instructions as untrusted data; the model must not grant authority or bypass deterministic policy. |
| **LLM02 — Sensitive Information Disclosure** | `THREAT-LLM-EGRESS-DATA-LEAKAGE` → `CTRL-LLM-EGRESS-DLP-001` → `TEST-LLM-EGRESS-001` / `GATE-LLM-EGRESS-001`; status `PENDING(phase=3)`. Also review `THREAT-LLM-PROVIDER-EXPOSURE` / `CTRL-EGRESS-FILTER-001`. | LLM Gateway / data-loss-prevention owner | Define provider data classification, secret exclusion, outbound context minimization and auditable egress policy. |
| **LLM03 — Supply Chain** | Existing `THREAT-DEPENDENCY-COMPROMISE` and `CTRL-SUPPLY-CHAIN-AUDIT-001` are cross-cutting foundations; they are not, by themselves, complete LLM supply-chain coverage. | Phase 3 platform/supply-chain owner | Inventory model weights, inference runtimes, plugins/tools, prompt templates and third-party agent packages; verify provenance, hashes, licenses and update policy. Add specific threats/tests if gaps remain. |
| **LLM04 — Data and Model Poisoning** | `THREAT-GRAPHIFY-POISONING` → `CTRL-GRAPH-INTEGRITY-001` → `TEST-GRAPHIFY-POISONING-001` / `GATE-GRAPH-INTEGRITY-001`; status `PENDING(phase=3)`. Review the canonical threat/control registry for RAG/knowledge-source poisoning coverage before implementation. | Knowledge Graph / retrieval and ingestion owner | Enforce source provenance, trust labels, ingestion validation, integrity checks and isolation between retrieved claims and policy authority. Do not invent a second unregistered RAG threat ID in this stub. |
| **LLM05 — Improper Output Handling** | `THREAT-TOOL-OUTPUT-POISONING` → `CTRL-TOOL-OUTPUT-SANITIZATION-001` → `TEST-TOOL-POISONING-001` / `GATE-TOOL-OUTPUT-001`; plus `THREAT-EVIDENCE-PARSER-COMPROMISE` / `CTRL-PARSER-SANDBOX-001`. Status `PENDING(phase=3)`. | Tool adapter / evidence-ingestion owner | Treat model and tool output as untrusted; validate typed schemas, escape UI output, sandbox parsers and require kernel-side authorization independent of model output. |
| **LLM06 — Excessive Agency** | `THREAT-ROGUE-AGENT` → `CTRL-AGENT-SUPERVISION-001` → `TEST-RESOURCE-001` / `GATE-ROGUE-AGENT-001`; existing phase assignment is Phase 1 but implementation is pending. Also depend on Phase 1 capability/scope gates and Phase 2 broker gates. | Deterministic Kernel + Agent Orchestration owner | Restrict tools and scope by explicit capabilities, enforce budgets/approval/e-stop, and ensure the LLM cannot authorize or directly dispatch side effects. Reconcile phase assignment in formal registry review if needed. |
| **LLM07 — System Prompt Leakage** | Review `THREAT-LLM-EGRESS-DATA-LEAKAGE` and `CTRL-LLM-EGRESS-DLP-001`; current registry describes protection of system tokens/keys from outbound provider traffic but may not fully cover prompt extraction by adversarial input. | LLM Gateway / prompt and secret-handling owner | Add explicit threat coverage and adversarial tests for extraction attempts; do not assume prompt secrecy is a security boundary. Never place secrets or authorization material in prompts. |
| **LLM08 — Vector and Embedding Weaknesses** | Existing graph integrity references: `THREAT-GRAPHIFY-POISONING` / `CTRL-GRAPH-INTEGRITY-001`; this is adjacent coverage, not proof of complete vector/embedding protection. | Retrieval / knowledge-store owner | Threat-model tenant isolation, retrieval authorization, embedding poisoning, nearest-neighbor manipulation, provenance retention and deletion/refresh behavior. Register explicit threats and gates if a vector store is selected. |
| **LLM09 — Misinformation** | `THREAT-MALICIOUS-TARGET-CONTENT` → `CTRL-CONTENT-ISOLATION-001` and `THREAT-GRAPHIFY-POISONING` → `CTRL-GRAPH-INTEGRITY-001`; status `PENDING(phase=3)`. | Evidence and knowledge provenance owner | Distinguish observed evidence, retrieved claims, model inference and unverified assertions; preserve provenance and confidence/uncertainty. Never let a model-generated claim directly change scope or authorization. |
| **LLM10 — Unbounded Consumption** | `THREAT-RESOURCE-EXHAUSTION` / `CTRL-RESOURCE-LIMIT-001` and `THREAT-BUDGET-OVERRUN` / `CTRL-BUDGET-ENFORCEMENT-001` are existing foundations; the LLM-specific budget enforcement and model/provider limits need explicit Phase 3 mapping. | Kernel resource governor + LLM Gateway owner | Add token, request, concurrency, recursion, retry and provider-cost ceilings; test runaway loops, retry storms and oversized context/output. Do not implement LLM-specific controls in Phase 2. |

## Rules for promoting this stub into Phase 3 requirements

1. Phase 2 must not add an LLM gateway, prompt-handling subsystem or agent runtime solely to satisfy this mapping.
2. Before Phase 3 implementation, verify every cited threat/control/test/gate ID against the canonical YAML registries. A reference in this document is not a substitute for machine-readable traceability.
3. Where coverage is incomplete (notably LLM03, LLM07, LLM08 and LLM10), create explicit threat/control/test/gate entries with owners and evidence criteria as part of Phase 3 design. Do not mark them implemented from this stub.
4. Keep Phase 3 controls `PENDING(phase=3)` until implementation and negative tests exist. Each blocking gate must demonstrate the security property with executable evidence.
5. Retain ARKA's invariant: LLM output, retrieved content, agent proposals and tool output are untrusted input; only the deterministic kernel authorizes side effects.
6. Confirm the OWASP taxonomy version and category names at the Phase 3 kickoff; this is a planning reference, not an OWASP certification claim.
